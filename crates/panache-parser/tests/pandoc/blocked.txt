# `Div`/`Plain`/`Div`. Remaining divergent `<div>`-family variants
# (verified 2026-07-08, not in corpus):
#   (1) multi-line SECOND div: `<div>a</div> y <div>\nz\n</div>` -> pandoc
#       `Div`/`Plain`/`Div`; the content-scan depth model treats the

# Line-block continuation lines that need blockquote/indent rules panache
# does not model yet (verified against pandoc 3.9.0.2, 2026-08-06):
#   508 `> | a\n b |` — pandoc's blockquote reader folds a lazy line into
#       the quote's raw content with its indentation dropped, so the line
#       cannot continue the line block and lands as a `Para` *inside* the
#       quote. Panache keeps the leading space and reads a continuation.
#       Classifying the lazy line correctly is easy; keeping it inside the
#       quote is not -- panache only holds a quote open across a lazy line
#       for an open Paragraph/ListItem/DefinitionList, so the same gap shows
#       up after a heading (`> # h\n b |`). Wants the general pandoc-dialect
#       blockquote-laziness rule, not a line-block patch.
#   509 `| a\n  | b` — pandoc tries `many (char ' ' >> anyLine)` *before* the
#       next `| ` marker line, so an indented marker line continues the line
#       above (`[[a, |, b]]`). Panache checks for a marker first. Swapping
#       the order needs 508's blockquote rule first: inside a quote the lazy
#       line's indent is dropped, so `> | a\n  | b` must stay two lines.
